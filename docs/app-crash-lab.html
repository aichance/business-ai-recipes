Try it with two commands

Node 22+ and npm required. Run this in an empty folder. The first command installs Chromium; the second fetches the pinned package from our GitHub release and runs three synthetic fixtures. No cloning, account or API key.

npx --yes --package=@playwright/test@1.64.0 playwright install chromium
npx --yes --package=https://github.com/aichance/business-ai-recipes/releases/download/app-crash-lab-v0.8.0/aichance-app-crash-lab-0.8.0.tgz app-crash-lab demo

Open the absolute index.html path printed in your terminal. Reports stay under .crash-lab/ in your current folder. The demo server stops automatically. Initial dependency/browser downloads need internet and disk space; Linux may need browser system libraries too.

Expected result: one reload failure, one rejected-update failure, and two passing checks for the fixed fixture. These are seeded defects, not a test of your own app.

Then test your app: create a starter in your working folder:

npx --yes --package=https://github.com/aichance/business-ai-recipes/releases/download/app-crash-lab-v0.8.0/aichance-app-crash-lab-0.8.0.tgz app-crash-lab init my-app.json

Can the app restore its own backup?

Download the app’s actual JSON, verify its selected saved records, restore the unchanged bytes in a fresh empty context, then compare every selected value again after reload. The unchanged local DevTasks control passes; its custom-category backup fails to restore.

0.8 also handles one declared HTML import preview/commit. The selected stored records must remain empty until that click; completion, full records and reload still have to match. TOEIC Tracker: one review, vocabulary and score; all ten exported domains includes the pinned app and repeatable configuration. 0.7 added one exact native restore confirmation. Tested beyond the bundled notes app

The same runner also checked a server-backed inventory fixture and an unchanged local build of Glypha. Glypha retained its saved scene and ETag after reload and a 422-rejected update. Its adapter adds configuration, not app-specific runner code.

Glypha is a passing control, not a bug discovery or evidence of author adoption. Checks cover selected values and explicit expectations; a URL alone does not define correct behavior. Cross-origin services, service workers, power loss and multi-user races are outside this first version.

Used on a real app, then reused on its next version

Sethera's author reported running both preservation checks and both generated Playwright tests on Windows, with Node 22.16.0 and Playwright 1.64.0. They then applied the same contract to Sethera v0.6.2 and reported both checks passing.

One independent user's public report, separate from our local compatibility tests. We have not replayed their raw logs or verified all Windows environments. Read the scope and use the Sethera example.
