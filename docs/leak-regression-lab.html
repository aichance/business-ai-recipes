02 / Your authorized test environment

自分のアプリで、同じ検査を。

既存のテスト環境と2ユーザーがある方向けです。準備が必要な内容を先に確認できます。

  1. 小さなソースZIPを展開Node 22以上。インストール・外部依存は不要です。
  2. テストデータを指定各ユーザーの行・非公開ファイルを1つずつ。設定例のID、期待する内容、ファイルのSHA-256を置き換えます。
  3. 認証情報は自分のPCだけにanonキーと2人の通常アカウントを .env.test に保存。作者への送信は不要です。
  4. 実行 → 変更 → もう一度実行新しい出力先で実行し、同じテスト契約の前後を比較します。
ZIPをダウンロードSHA-256
AFTER CONFIGURATION / Node 22+
node cli.mjs check --env .env.test \
  --config test-config.json \
  --out ./leak-check-before --live

# 設定変更後、別の出力先で再実行
node cli.mjs check --env .env.test \
  --config test-config.json \
  --out ./leak-check-after --live

node cli.mjs compare \
  --before ./leak-check-before/report.json \
  --after ./leak-check-after/report.json

0 = 指定範囲はPASS / 2 = 露出を確認 / 3 = 判定できない観測あり
初回の入力・設定エラーは1。出力フォルダは毎回新しくします。

認証・書き込み・削除を含むアプリ全体の安全性を保証するツールではありません。テスト対象と意図を指定した読み取り検査です。設定例・手順・検査の範囲を読む ↗

ローカルSupabase 1環境で、所有権2構造 × 設定6状態。公開ZIPを展開し直したコードで、実際の認証・DB・Storageに168の読み取り観測を行いました。CLI 2.24.3 / Node 22.23.4。第三者の本番アプリや最新ホステッド環境の検証とは区別しています。

検査しないこと

書き込み・削除、署名付きURL、画像変換、キャッシュ残存、Realtime、RPC、業務ロール、ブラウザのセッション。1MiB超の応答も対象外です。意図的な公開データを非公開契約に含めないでください。
